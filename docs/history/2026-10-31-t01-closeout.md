## 模型品質界線

## 恢復與重驗

先從 main 取得本文件、[收據與壓縮 manifests](2026-10-31-t01-archive/receipt.json) 和 [驗證工具](../../scripts/verify_t01_archive.py)。原始實驗 tag 指向 `a47fb16cd8059dd7830e8d2a0cd0a6928c38c6d4`；封存的 Git bundle 保存 main 的 merge commit、原工作分支與 annotated tag 三個 refs 及其完整祖先。

先檢查三卷、原始 manifests 與完成收據。這會重新讀取全部壓縮 bytes、核對 SHA-256 並執行 `zstd -t`；成員逐檔核對則見製作時的完整串流比對收據，或以下解壓後的驗證：

```sh
archive_root="$HOME/.cache/saccade-v1/archives/t01-experiment-final-2026-10-31"
python3 scripts/verify_t01_archive.py --archive-dir "$archive_root"
```

完整恢復需要約 92 GB 的額外解壓空間；將 `restore_parent` 設為至少 100 GB 可用空間的可寫位置，以 `mktemp` 建立全新 staging。以下是供恢復時執行的命令；本次沒有執行全量解壓，實際抽取範圍以收據為準。

```sh
restore_parent=/mnt
restore_root=$(mktemp -d "$restore_parent/t01-restore.XXXXXX")
for bundle in core formal-feature-cache negative-feature-cache; do
  tar --use-compress-program=zstd --extract \
    --file "$archive_root/$bundle.tar.zst" --directory "$restore_root" \
    --no-same-owner --no-same-permissions
done
python3 scripts/verify_t01_archive.py --root "$restore_root" --manifest \
  docs/history/2026-10-31-t01-archive/core-manifest.json.gz \
  docs/history/2026-10-31-t01-archive/formal-feature-cache-manifest.json.gz \
  docs/history/2026-10-31-t01-archive/negative-feature-cache-manifest.json.gz
```

Tar members 保存原絕對路徑去掉開頭 `/` 的布局。檔案驗證會檢查全部 listed regular files 的 size／SHA-256、directory type 與 symlink target，不跟隨 symlink；上述解壓旗標不恢復原 owner／mode。壓縮 manifests 解開後的 bytes 與外部原始 JSON 相同，hash 由 Git 內的 receipt 固定。完整外部收據若遺失，可由 Git receipt 核對 archives，從各卷還原其內嵌的 `receipts/*-manifest.json`，再還原 Git 保存的其他收據。
